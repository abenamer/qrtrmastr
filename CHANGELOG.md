# Changelog

## 0.1.0 — unreleased

- The tables of `qm due`, `qm due --gap` and `qm due --simple` put each quantity and each date under its column title, and the number of an addition in a column; the column of the reason is wide enough for the longest reason. Before, a quantity, a date and a number were printed without the width of their column, so a title stood one or more places beside its values. Nothing else that `qm` prints changes. For a developer: tests for the last gaps of the plan (two writers of one message, a write that fails late in a transaction, the real reader of a mail in the tests of the import, the binary as a user starts it), and tests for the rules that a run of `cargo mutants` found without one ([Develop and run](docs/runbooks/develop.md#develop-mutation-testing)).
- A backup of the database and a proof that it restores: `scripts/restore_drill.sh backup` writes one file to `backups/`, and `scripts/restore_drill.sh` restores a new backup into a second PostgreSQL container that is thrown away and compares each table with the database ([Back up the database and restore it](docs/runbooks/backup-and-restore.md)). The script reads the database and writes nothing to it. `qm` does what it did. For a developer: the count of unsafe code of each dependency is in `unsafe-baseline.tsv`, and the `rust` job fails when a change moves it without a new baseline ([ADR 0018](docs/decisions/0018-records-for-the-dependencies-the-two-sensitive-components-and-the-backup.md)); three new pages record the unsafe code on the paths of a mail, what each dependency runs on the build machine, and a design review of the redactor and the Gmail adapter with 17 findings, 8 of them new.
- Three inputs that the database refuses stopped `qm import` at one mail on each run, and no longer do. A product name whose normalized form is longer than 1,024 bytes is a row that the parser cannot read, an anomaly; before, the database refused its alias and the parse step stopped at that receipt, so no receipt after it was parsed. A `Message-ID` longer than 998 bytes, or with a NUL character, is not the message key: the hash of the message is; before, the database refused a key that its index could not hold, and no mail after it was stored. A mail with a NUL character in its subject or in its text is reported as `malformed` and the import continues; the text of a mail that has only an HTML part is made from the HTML, where the reference `&#0;` also gives the character. Before, the database refused the row and no mail after it was stored. A real receipt has none of the three. A key that is already stored keeps its length.
- An amount of money holds its currency, is at most $99,999,999.99, and its sums are checked (REAS-RUST-008). A number above that is no amount, and a quantity or a weight of 10,000,000 or more is no quantity: a line with such a final price or quantity is a row that the parser cannot read, and a unit price, an options price or a weight of that size is left out of its line. Before, such a number was read, the database refused its row, and each later run of `qm import` stopped at that message, so no receipt after it was parsed. A receipt in which a sum, a product or a gap of its amounts is more than that number is a failed attempt and stores no order; before, it was stored, in most cases as not reconciled. That needs an amount of eight digits before the point, or more than 100,000 lines. A zero that a receipt prints with a minus sign is shown as `$0.00` in an anomaly, was `$-0.00`. Clippy refuses arithmetic on a float. For each other receipt nothing changes, and `qm due --json` writes the same text.
- Each of the seven readers of outside data has a fuzz target ([ADR 0017](docs/decisions/0017-fuzz-targets-with-cargo-fuzz-and-a-budget-for-each-stage.md)); a new workflow runs them on each pull request and once a day, built for the machine that runs them. Their first runs and their review found four defects, corrected here. A `Message-ID` that holds your phone number inside a longer run of digits, a term between `<` and `>`, or a term after a `%`, is no longer stored as the message key: the key is then the hash of the message. A link with such an address loses its address (redaction version 8). A mail without a sender domain gets no DKIM pass. `qm fetch` refuses a page of the message list that holds an id that is no id before it reads a message of that page; before, it read the messages that came first. Nothing else that `qm` does changed.
- Development and CI use Rust 1.100.0, the latest stable release and the version of the image that builds `qm`; they were at 1.99.1 while the image had moved to 1.100. Run `cargo` once in the repository and rustup installs it. The `qm` of the image does what it did. A `qm` that you build with `cargo` can now print a text with a combining mark in another form inside a quoted value of an error, because the newer standard library escapes more of them.
- The rules that keep a Claude session out of your data name no person: `.claude/settings.json` denies `~/qm-data`, your configuration and state directories, a page of `qm due --html` at the top of the repository, and a mailbox or message file in any place, for whoever cloned the repository. `.claude/settings.local.example.json` is an example for directories in another place, and the README says so. The privacy canary reads every tracked file except images, lockfiles and the synthetic inputs, so also `.claude/`, the workflows, the scripts and the vendored standard, and it fails on the home directory of a person. Nothing that `qm` does changed.
- Each committed file has an authority class in [docs/reference/files.md](docs/reference/files.md): authored, derived, evidence or companion (REAS-DOC-002). The documentation checker fails on a committed or staged file that the table does not name. Git ignores a new snapshot (`*.snap.new`) that a failed test leaves. Nothing that `qm` does changed.
- `qm due --json` is written from wire types in the command-line adapter (`src/adapters/cli/wire.rs`), and the domain and the application layer carry no serialization (REAS-DATA-001). The JSON is the same, byte for byte, for every report that was compared. `qm fixture add` takes the key as before, and also with its kind before it, `message_id:<text>` or `sha256:<text>`; a key that is empty, that starts or ends with a space, or that is named `sha256` and is not 64 lowercase hexadecimal digits is refused with status 2. Its two error lines, for a key that is not stored and for a message without an HTML body, now show the key with its kind. A stored message key that does not fit its kind stops `qm import`, `qm fetch` and the parse step with an error that names the row; no such row is known. `scripts/check.sh layers` fails when the domain or the application layer names a dependency that the script does not list for that layer, such as serde or SQLx.
- Each public item of the adapters has a doc comment, and Clippy now refuses a public item without one (REAS-RUST-009). The help of `qm drop` and of `qm fixture add` describes the argument, and the help of `qm due --include-tentative` says which items it adds.
- Each public item of the domain and the application layer has a doc comment (REAS-RUST-009). No behaviour changed.
- A lint that is taken out of `Cargo.toml`, or lowered, fails the `rust` job: `examples/lint_canary.rs` holds one planted violation of each lint, and `scripts/check.sh planted` asserts that each one fires.
- `scripts/check.sh` is the one list of the checks: `scripts/check.sh all` runs every group except `sqlx`, CI and the Stop hook call its groups, and a workflow that runs one of its commands without it fails the `privacy` job. The `rust` job also builds the documentation with warnings denied. A new workflow, `scan.yml`, runs the audit and the deny check once a day.
- The documentation checker also fails on a page without an `updated` date, a page that the index does not reach, a link to a heading that does not exist, and a retired term. Each page of `docs/` has its date, and `docs/terminology.md` has a table of retired terms. The checker needs `markdown-it-py`: run `pip install -r requirements-docs.txt` again. [ADR 0016](docs/decisions/0016-the-documentation-checker-follows-the-checker-of-reas.md).
- Arithmetic and reads by position in `qm` are checked (REAS-SEC-003): a number at the bound of its type gives an answer and does not stop the program (no such stop is known from a real receipt), and Clippy refuses new unchecked arithmetic, an index and a cut of a text outside tests. Each pattern has a size limit of 1 MiB; a redaction term or a phone number of several hundred characters is refused when the redactor is built. No result changed for a value that `qm` accepted before.
- A character that a terminal obeys (an escape sequence, a line break, a direction mark) in a product name from a receipt, in the Message-ID of a mail or in a file name is shown as text, `\u{1b}`, in the tables of `qm due`, the report of `qm import` and `qm fetch`, the error line and the log. `qm due --json` writes such a character as a JSON escape; the value is the same.
- `rust-toolchain.toml` pins Rust 1.99.1 for development and CI, the version the image is built with.
- A mail whose Message-ID or link holds a `%`, one character and then a character of more than one byte no longer stops `qm import` and `qm fetch`. In a release build an arithmetic overflow stops the program with an error; the number does not wrap. `Cargo.toml` declares the lint levels of REAS 1.6.0-draft; `docs/runbooks/develop.md` says how to work with them.
- The project follows REAS 1.7.0-draft (it was 1.4.0-draft): the vendored copy in `standards/reas/` is new, the [self-audit](docs/self-audit.md) lists each rule with its status, and [ADR 0015](docs/decisions/0015-reas-1-7-0-draft-and-the-order-of-its-gaps.md) gives the ten steps that close the gaps. No behaviour of `qm` changed.
- `qm fetch` reads new receipts from the Gmail API with read-only access, after a one-time `qm gmail login`. Setup in `docs/runbooks/gmail-fetch.md`. [ADR 0013](docs/decisions/0013-new-receipts-are-fetched-from-the-gmail-api.md).
- `qm due --html` prints the next order as a web page; `scripts/due_page.sh` writes it to your exports directory. [ADR 0012](docs/decisions/0012-the-next-order-as-a-page-that-is-a-file.md).
- `qm due` prints essentials, extras, a shuffled "remember this?" list and your own additions. `qm add ITEM` adds an item by hand and asks for the reason (ran out, almost running out, making a recipe, new food to try, repeat favorite); `qm drop NUMBER` removes it. Migrations `0005_list_additions.sql`, `0006_addition_reason_running_low.sql`. [ADR 0011](docs/decisions/0011-essentials-extras-reminders-and-additions-with-a-reason.md).
- `qm due` counts the sizes of one product as one, and leaves out a product bought in bulk until the stock is expected to run out. [ADR 0010](docs/decisions/0010-sizes-of-one-product-count-as-one-and-a-bulk-purchase-is-a-stock.md).
- `qm due` lists the products most often in your latest orders (the habit rule, `--top N`); the gap rule moved to `--gap`. A backtest over 60 held-out orders is in [ADR 0009](docs/decisions/0009-qm-due-ranks-by-recent-habit.md).
- Receipts parse: the FreshDirect parser, version 2, reads the real receipt layout of 2017 to 2026, and a receipt without a DKIM pass is parsed and its order tagged `non-verified` instead of refused. Migration `0004_order_sender_check.sql`. [ADR 0008](docs/decisions/0008-receipts-without-a-dkim-pass-are-parsed-and-tagged.md).
- Redaction, versions 3 to 7: a pass for a long term without a word boundary; card digits after a brand, the word "card" or a wallet name; an email address is removed whole when a term inside it, in the local part or in the domain, was replaced first; the terms are replaced before the phone numbers as well as after, so the country code of a phone number no longer takes the last digit of the ZIP code of your address. The privacy canary's term mode skips the owner segment of a GitHub address. It scans a file with a NUL or a byte that is not UTF-8 as text, where it passed such a file before.
- `qm import` reports refusals by cause: one `REFUSED <count>: <cause>` line for each cause (platform, message kind, part, kind of term, the check that found it), and the line per message only for twenty refusals or fewer. A cause never carries the text.
- Restaurant mail is stored at import: besides FreshDirect, `qm import` stores the redacted order mail of Seamless, Grubhub, Toast, Square, Clover and DoorDash, found by exact sender address (`[import.restaurant_senders]` in the configuration). No parser reads it yet. The report has a line of new messages by platform. Migration `0003_restaurant_platforms.sql`. [ADR 0007](docs/decisions/0007-restaurant-mail-is-stored-at-import-and-parsed-later.md).
- Import a folder of Takeout archives: `qm import --takeout <path>` takes a folder of the `.zip` files as Google delivers them, one archive, or one mailbox file. Archives are read in place, nothing is extracted, and one message is in memory at a time, so an export of the whole mailbox works. `--mbox` stays as an alias. New dependency: `zip`, inflate only. [ADR 0003](docs/decisions/0003-one-time-takeout-import-with-the-gmail-api-deferred.md).
- Dependencies: `jiff` replaces `chrono` for every date and time, and the unused `chrono-tz` is gone. Two advisories report both crates as unmaintained, and the `deny` job failed on them. Nothing changes in the commands or in the stored data. [ADR 0014](docs/decisions/0014-dates-and-times-with-jiff-not-chrono.md).
- First run: the README, `qm --help` and `qm import --help` say that the tool needs a Google Takeout export of your FreshDirect mail and how to request one. An export that cannot be opened is now an error with status 1 that names the file to look for and the runbook; before, it was a `malformed` line and status 0. A missing `[redaction]` section prints the section to add and where the file lives.
- Process: a Dependabot pull request is never merged as it stands; its bump is redone on a reviewed branch by the commit protocol, and Dependabot's version updates arrive grouped per ecosystem once a month. `actions/checkout` moves to 7.0.1 and `gitleaks/gitleaks-action` to 3.0.0 (Node 24 runtime). [ADR 0002](docs/decisions/0002-pull-requests-and-the-security-review-on-every-commit.md).
- Process: the security review on every commit is literal, including documentation-only, canary and hook changes; recorded in `CLAUDE.md` and [ADR 0002](docs/decisions/0002-pull-requests-and-the-security-review-on-every-commit.md).
- Run as a container: `Dockerfile` and a `qm` service in `compose.yaml` under a profile, so `docker compose up -d` starts the database and `docker compose run --rm qm <command>` runs the tool with your exports at `/data`, your configuration at `/config` and the local fixtures at `/fixtures`. Nothing is installed on the host.
- Import and recommend (milestone 1): `qm import --mbox <path>` reads a Google Takeout export of the FreshDirect label, redacts each message before storing it once, parses every receipt in the 2026 layout into an order with its lines, keeps rows it cannot classify as anomalies, resolves products through aliases, and writes each attempt in one guarded transaction; `qm due` lists what the usual gap between purchases says you are about to run out of, with `--simple` for the frequency rule and `--json`; `qm fixture add` writes a stored redacted receipt as a local fixture. Configuration in `~/.config/qrtrmastr/config.toml`: redaction terms, thresholds, senders. [ADR 0003](docs/decisions/0003-one-time-takeout-import-with-the-gmail-api-deferred.md), [ADR 0004](docs/decisions/0004-redaction-before-storage.md), [ADR 0005](docs/decisions/0005-product-identity-through-aliases.md), [ADR 0006](docs/decisions/0006-recommendation-by-usual-gap-with-a-simple-rule-beside-it.md).
- Scaffold (milestone 0): the Cargo package `qrtrmastr` with the binary `qm`, the REAS layout (`src/domain`, `src/application`, `src/adapters`, `src/main.rs`), identifier newtypes, exact money and quantities, the stored labels and the `ParseState` lifecycle, the `SchemaStore` port and the `Migrate` use case, `PostgresStore`, and `qm migrate`. Migrations `0001_raw_mail.sql` and `0002_grocery.sql` create the MVP schema. CI with seven required jobs (format, check, clippy, migrations, checked queries, tests; audit; deny; gitleaks; privacy canary; docs; dependency review), Dependabot, the Compose file with a named volume, and the Claude Code setup. [ADR 0001](docs/decisions/0001-ports-and-adapters-for-a-private-tool.md) and [ADR 0002](docs/decisions/0002-pull-requests-and-the-security-review-on-every-commit.md).
